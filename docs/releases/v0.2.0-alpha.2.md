# Neon HUD 0.2.0-alpha.2 — hover follows the screen

Hover readings now open toward the available space around the floating pill.

- At the bottom of the screen, readings appear above the HUD; at the top, they appear below it.
- At the right edge, readings appear to the left; at the left edge, they appear to the right.
- At corners, readings open diagonally inward and stay inside the monitor containing most of the HUD.
- Moving or compressing the pill updates the next hover placement. Cached monitor bounds keep the calculation light, and hovering does not resize the pill or write preferences.

## Validation

[Exact-source Windows and Mac CI](https://github.com/ajaxcbcb/neon-hud/actions/runs/37602211912) passed for source `173101a3a8f5eeaf4f85ac6c043de7e05607e5cb`: eight native tests on each platform, 31 Windows and 28 Mac core tests in both desktop and headless configurations, formatting, dependency closure, locked builds and packages.

An actual Windows cursor check exercised all four edges and all four corners. Every popup opened inward within the monitor work area, and captured native output was inspected. Geometry tests also cover compressed and regular pills, movement, negative monitor origins, display scaling and small displays. Mac placement tests and builds passed; Mac interaction remains unverified. See the [validation log](../VALIDATION.md) for the separate installed-app evidence.

## Downloads

Windows x64 uses the portable ZIP: extract it and run `neon-hud-native.exe`. Apple Silicon Macs have a DMG and an app ZIP. Packages include the Apache 2.0 and MIT licenses, third-party notices and font licenses; `SHA256SUMS.txt` lists the package checksums.

This remains an unsigned native preview. Intel Mac packaging, signed native automatic updates and strict single-process provider connections remain open. The native preview reuses its existing saved preferences. The stable updater manifest remains unchanged, and the Windows preview requires an OpenGL 2.0 graphics driver.
